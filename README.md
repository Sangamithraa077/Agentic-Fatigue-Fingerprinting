# Agentic Fatigue Fingerprinting

**Agentic AI Framework for Personalized Explainable Fatigue Fingerprinting Using Multimodal Wearable Sensor Data**

An open-source biomedical AI research framework for detecting and characterizing muscle fatigue from multimodal wearable sensor data (EMG, IMU, PPG), built toward personalized, explainable, agent-driven fatigue analysis.

## Overview

This project builds a complete, reproducible pipeline — from raw wearable sensor data to explainable, personalized fatigue predictions — on top of the [WSD4FEDSRM](#dataset) dataset (EMG, IMU, and PPG recordings during a shoulder-fatigue protocol). Each stage is implemented as an independently tested, documented module, so the pipeline can be extended (multimodal attention fusion, personalization, explainability, agentic reasoning) without rewriting earlier stages.

**Design principles carried through every phase:**
- Raw data is never mutated — every stage produces new, typed objects from the previous stage's output.
- Every reusable component ships with unit tests and a design-rationale doc in [`docs/`](docs/).
- Every analysis phase ships with a reproducible report + figures in [`reports/`](reports/), generated by a runnable script in [`notebooks/`](notebooks/) — not hand-written.
- Data quality issues are surfaced and documented, never silently patched over (see the Reports section below for two real corruption findings caught this way).

## Key Features

- **Typed dataset loader** for the raw WSD4FEDSRM archive — no nested dictionaries, full dataclass object graph (`Dataset → Subject → Condition → {EMG, IMU, PPG, Labels}`).
- **Modality-specific signal preprocessing** (EMG band-pass/rectification, IMU gap-filling/consistency checks, PPG baseline-drift removal), each step documented with its biomedical rationale.
- **Configurable feature engineering** — sliding-window EMG/IMU/PPG feature extraction (time-domain, frequency-domain, per-axis, resultant-vector, peak-based).
- **Feature validation & selection framework** — missing/infinite/constant/near-zero-variance/duplicate/correlation checks, mutual-information and ANOVA importance *diagnostics* (never auto-applied — recommendations only).
- **Baseline modeling framework** benchmarking 4 classical ML models and 4 deep learning architectures under identical, leakage-safe, group-aware evaluation protocols.
- Built to extend into **multimodal attention fusion, leave-one-subject-out personalization, SHAP explainability, and agentic reasoning** (upcoming phases).

## Dataset

**WSD4FEDSRM** — *Wearable Sensor Data for Fatigue Estimation during Shoulder Rotation Movements* (Yasar, Sica, O'Flynn, Tedesco & Menolotto, 2024).

- 34 healthy participants performing internal/external shoulder rotation at 30–60% MVIC until volitional exhaustion (Borg RPE 20), plus MVIC calibration trials.
- Sensors: surface EMG (6 muscles, 1000 Hz), IMU (6 body locations, 100 Hz), PPG (finger, 200 Hz) — PPG and Borg labels are present only for the fatigue-task trials, not the MVIC calibration trials.
- License: **CC BY 4.0**. Dataset DOI: [10.5281/zenodo.8415066](https://doi.org/10.5281/zenodo.8415066). Paper: [Yasar et al., *Scientific Data* 11, 433 (2024)](https://doi.org/10.1038/s41597-024-03254-8).
- Not included in this repository (see [`.gitignore`](.gitignore)) — download from Zenodo and extract to `datasets/raw/WSD4FEDSRM/` before running the pipeline (see [Quickstart](#quickstart)).

## Installation

Requires Python 3.10+.

```bash
python -m venv venv
source venv/bin/activate  # On Windows: venv\Scripts\activate
pip install -r requirements.txt
```

## Quickstart

1. **Get the dataset.** Download `WSD4FEDSRM.zip` from [Zenodo](https://zenodo.org/records/8415066) and extract it to `datasets/raw/WSD4FEDSRM/`.
2. **Load it** into the typed object model:
   ```bash
   python -m ml.preprocessing.dataset_loader
   ```
3. **Run any phase's report end-to-end** (loads data → preprocesses → extracts features → analyzes/trains → writes a report + figures):
   ```bash
   python notebooks/phase6_eda_analysis.py               # Exploratory data analysis
   python notebooks/phase8_feature_engineering_report.py  # Feature extraction report
   python notebooks/phase8_5_feature_validation_report.py # Feature validation & selection report
   python notebooks/phase9_baseline_models_report.py      # Classical + deep learning benchmarks
   ```
   Each script is the actual, reproducible source of its corresponding report under `reports/` — nothing in `reports/` is hand-written.

## Roadmap

The modeling framework in `ml/models/common/` (group-aware splitting, shared config, evaluation protocol) was deliberately built to be reused, unmodified, by the phases below:

- **Multimodal attention fusion** (`ml/models/fusion/`) — combine EMG/IMU/PPG at the representation level instead of the tabular-feature-vector approximation used for the Phase 9 baselines.
- **Personalization** (`ml/models/personalization/`) — leave-one-subject-out adaptation, using the same group-aware splitters already built around `subject_id`.
- **Explainability** — SHAP-based interpretation of both baseline and fusion models, consuming the predictions/probabilities already saved under `ml/models/artifacts/`.
- **Agentic reasoning** (`backend/agents/`) — LLM-driven personalized fatigue narratives and recommendations.
- **Dashboard & API** (`dashboard/`, `backend/api/`) — serving predictions and explanations.
